## 📋 Executive Summary & Результаты Глубокого Системного Аудита

В результате проведенного системного аудита кодовой базы (`WbBridge.kt`, `ProductRepositoryImpl.kt`, `WbApiService.kt`, `WbDatabase.kt`, `MainActivity.kt`, `WorkManagerScheduler.kt`, `PriceUpdateWorker.kt`, `WbArticleExtractor.kt` и `index.html`) выявлен ряд скрытых краевых случаев (edge cases), логических рассинхронизаций и потенциальных точек отказа:

1. **Рассинхронизация настроек интервала синхронизации `WorkManager`**:
   - В UI (Экран Профиля) пользователь может выбрать интервал фоновой синхронизации ("1 час", "3 часа", "6 часов", "12 часов").
   - В `UserPreferencesRepository.kt` значение сохраняется в `SharedPreferences`, однако `WorkManagerScheduler` вызывается только один раз при старте `MainActivity` со статическим значением по умолчанию (6 часов). Изменение настройки в интерфейсе **не приводит к перезапуску и перепланированию задач `WorkManager`**.

2. **Чрезмерная мягкость извлечения артикулов в `WbArticleExtractor.kt`**:
   - Крайний фоллбек `trimmed.filter { it.isDigit() }.toLongOrNull()` извлекает числа из любых посторонних ссылок (например, `https://example.com/item/12345`), если регуляторные выражения WB не сработали. В результате приложение выполняет заведомо обреченные сетевые запросы к CDN Wildberries для невалидных артикулов.
   - Отсутствует строгая валидация длины артикула WB (норма: от 5 до 12 цифр) и защита от нулевых/неадекватных целевых цен в `saveTargetPrice()`.

3. **Связывание JS Bridge при холодном старте WebView**:
   - Функция `initTheme()` в `index.html` выполняется инлайн до момента полного внедрения `@JavascriptInterface WbBridge` в глобальный контекст `window`. В ситуациях сброса WebStorage тема откатывается к значениям по умолчанию без синхронизации с нативными `SharedPreferences`.

4. **Блокировка вертикального скролла элементами `<canvas>`**:
   - В модальном окне детализации и на экране Аналитики элемент `<canvas>` при перетаскивании пальцем может перехватывать жесты вертикальной прокрутки контейнера, снижая гладкость скролла на мобильных устройствах.

## 🎯 Разбиение на Независимые Этапы Реализации v7.0

### 📡 Этап 1: Сетевая Устойчивость и Автообновление Цен в Фоновом Режиме (`SyncScheduler` / `WorkManager`)

#### 1.1. Динамическое Перепланирование `WorkManager`
- **Проблема**: Изменение интервала фонового обновления в UI не обновляет расписание задач Android WorkManager.
- **Решение**:
  1. Добавить метод в [`WbBridge.kt`](file:///home/yura/projects/wbtracker/app/src/main/kotlin/com/wbtracker/app/bridge/WbBridge.kt):
     ```kotlin
     @JavascriptInterface
     fun setSyncInterval(intervalJson: String): String
     ```
  2. Парсить переданное значение (1, 3, 6, 12 часов), вызывать `userPreferencesRepository.setSyncInterval(intervalStr)` и совершать повторный вызов `syncScheduler.schedulePeriodicUpdate(intervalHours)`.
  3. В [`WorkManagerScheduler.kt`](file:///home/yura/projects/wbtracker/app/src/main/kotlin/com/wbtracker/app/data/worker/WorkManagerScheduler.kt) применять политику `ExistingPeriodicWorkPolicy.UPDATE`, гарантируя моментальное замещение фоновой задачи новым интервалом без дублирования.

#### 1.2. Сетевая Отказоустойчивость и Таймауты
- **Проблема**: При нестабильном интернет-соединении сетевые запросы к Wildberries CDN и Price API могут зависать.
- **Решение**:
  1. В [`WbApiService.kt`](file:///home/yura/projects/wbtracker/app/src/main/kotlin/com/wbtracker/app/data/remote/WbApiService.kt) закрепить жесткие таймауты: `connectTimeout = 6s`, `readTimeout = 6s`, `callTimeout = 8s`.
  2. В параллельном опросе корзин CDN (`basket-01` .. `basket-45`) использовать `withTimeoutOrNull(6000L)` и безопасную отмену незавершенных корутин при первой успешной корзине.
  3. В [`ProductRepositoryImpl.kt`](file:///home/yura/projects/wbtracker/app/src/main/kotlin/com/wbtracker/app/data/repository/ProductRepositoryImpl.kt) транслировать детальные русскоязычные сообщения об ошибках ("Ошибка DNS", "Превышено время ожидания сервера WB", "Товар не найден").

#### 1.3. Обработка Уведомлений в `PriceUpdateWorker`
- **Проблема**: Повторные фоновые проверки могут приводить к спаму уведомлениями при незначительных колебаниях цены.
- **Решение**:
  1. Проверять `NotificationRuleEntity` на достижение `targetPrice`.
  2. После отправки сгруппированного уведомления через `WbNotificationHelper` деактивировать сработавшее правило (`isActive = false`), предотвращая повторные алерты до перенастройки пользователем.

### 🛡️ Этап 2: Валидация, Фильтрация Ввода и Адаптивные Уведомления

#### 2.1. Строгая Валидация Артикулов в `WbArticleExtractor`
- **Проблема**: Некорректные ссылки и произвольные наборы цифр попадают в сетевой пайплайн.
- **Решение**:
  1. Очистить входную строку от спецсимволов, пробелов, переносов и Unicode-мусора.
  2. Удалить опасный фоллбек `trimmed.filter { it.isDigit() }`.
  3. Принимать только аргументы, соответствующие Regex шаблонам Wildberries, с длиной артикула строго в диапазоне **$5 \le \text{length} \le 12$** digits.
  4. Если ввод не прошел валидацию — возвращать `null` и выводить понятное адаптивное уведомление: `"Неверный артикул WB. Артикул должен содержать от 5 до 12 цифр."`

#### 2.2. Валидация Целевой Цены (Target Price)
- **Проблема**: Ввод 0 ₽, отрицательных значений или астрономических чисел в модальном окне детализации.
- **Решение**:
  1. В `index.html` в функции `saveTargetPrice()` ввести проверку:
     $$1 \le \text{targetPrice} \le 1\,000\,000\text{ ₽}$$
  2. При нарушении диапазона выводить красное тост-уведомление `top-toast error`.

#### 2.3. Высококонтрастные Адаптивные Top Toast Уведомления
- **Проблема**: Необходимость четкого визуального разделения статусов операций в Светлой и Тёмной темах.
- **Решение**:
  1. Применить стили `backdrop-filter: blur(12px)`.
  2. Тёмная тема: `success` (зеленый фон `#14532D`, текст `#4ADE80`), `error` (красный фон `#7F1D1D`, текст `#F87171`), `search` (фиолетовый фон `#581C87`, текст `#E9D5FF`).
  3. Светлая тема: `success` (светло-зеленый `#DCFCE7`, текст `#14532D`), `error` (светло-красный `#FEE2E2`, текст `#7F1D1D`), `search` (светло-фиолетовый `#F3E8FF`, текст `#581C87`).

### ⚡ Этап 3: Оптимизация UX-Анимаций, 0ms Lag и Изоляция Компонентов

#### 3.1. Мгновенное Переключение Вкладок (0ms Lag)
- **Проблема**: Тяжелая отрисовка Canvas-графиков во время переключения вкладок вызывала просадку FPS.
- **Решение**:
  1. В `index.html` функция `switchTab()` мгновенно меняет CSS-классы `active` для экранов и навигационной панели.
  2. Тяжелая генерация Canvas-графика для вкладки «Аналитика» выносится в отложенный блок:
     ```javascript
     setTimeout(() => {
       requestAnimationFrame(() => {
         renderAnalyticsScreen();
       });
     }, 350);
     ```

#### 3.2. Гладкий Вертикальный Скролл и Изоляция Canvas
- **Проблема**: Нажатие пальцем на область Canvas перехватывало скролл страницы.
- **Решение**:
  1. Добавить в CSS для элементов `<canvas>` свойство `touch-action: pan-y;` или `pointer-events: none` для подложки графика.
  2. Гарантировать, что вертикальный скролл страницы не блокируется при задевании холста графика.

#### 3.3. Защита от Частых Кликов (Debouncing & Request Locks)
- **Проблема**: Быстрое многократное нажатие на кнопки «Добавить», «Удалить» или «В избранное» приводит к параллельным вызовам БД и искажению состояния UI.
- **Решение**:
  1. Ввести флаги состояния `isSubmittingAdd = false`, `isTogglingFav = false`.
  2. Блокировать повторные нажатия до завершения текущего асинхронного вызова Bridge.

#### 3.4. Синхронный Сохраняемый Темы-Контроллер
- **Проблема**: Белый мигающий экран при старте приложения на тёмной теме.
- **Решение**:
  1. IIFE скрипт `initTheme()` сразу при инициализации HTML применяет `data-theme` на `document.documentElement` до рендеринга DOM.
  2. Нативное значение темы из `UserPreferencesRepository` синхронизируется через `WbBridge.getDarkTheme()` при старте.
